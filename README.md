# 眨眼报警助手 (Blink Alarm)

面向渐冻症（ALS）患者的 Windows 桌面软件：用摄像头监测眼睛的开合，**在设定时间内连续眨眼 N 次（默认 10 秒内 5 次）即触发报警**，并可选联动 Home Assistant / 米家等外部设备。

2.0 版用 **C# / .NET 8 + WPF** 完全重写：

- 识别：MediaPipe Face Mesh（478 点面部关键点）模型，经 **ONNX Runtime** 在本机推理，不联网、不上传画面
- 判定：对左右眼分别计算 EAR（眼睛纵横比），与校准得到的睁眼基准相除，得到**眼睛开合度**；经「睁眼 → 闭眼 → 重新睁眼」状态机确认一次完整眨眼
- 界面：全新的简洁界面，大按钮、大字号，方便用**眼控仪**操作
- 报警：本机警笛声、USB 继电器外接警报器、Home Assistant 等 Webhook 联动，可同时使用
- 发布：单个 `BlinkAlarm.exe`，完整版自带运行库和模型，**不需要安装 Python 或 .NET**

## 二、使用

1. 让使用者正对摄像头，面部光线充足。
2. 点击绿色的 **开始监测**。
3. 画面中央出现「正在校准」时，**自然睁眼正视摄像头约 2 秒**，软件会记下睁眼时的基准。
4. 校准完成后左上角显示「监测中」。画面下方两条进度条是左右眼的实时开合度，眼睛轮廓睁眼为绿色、闭眼为红色。
5. 在时间窗口内连续眨眼达到设定次数，即触发报警：画面变红、响起警笛，并显示一个很大的 **停止报警** 按钮（也可以按 `Esc`）。

右上角的卡片显示当前计数（如 `3 / 5`）和这一轮计数的剩余时间。

### 设置

所有设置改动后立即生效，并自动保存到 exe 同目录的 `config.json`（该文件夹不可写时保存到 `%AppData%\BlinkAlarm`）。旧版的 `config.json` 可以直接沿用。

**触发**

| 设置项 | 说明 |
| --- | --- |
| 摄像头编号 | 内置摄像头一般是 0，外接 USB 摄像头试 1、2…；监测中切换会自动重新打开。 |
| 灵敏度 | 0~100，默认 60。越高越容易判定为闭眼；下方会显示对应的开合度阈值。眨眼识别不到就调高，误触发多就调低。 |
| 眨眼次数 | 触发报警需要的眨眼次数（2~10，默认 5）。 |
| 时间窗口 | 这些眨眼需要在多少秒内完成（3~30，默认 10）。 |
| 报警冷却 | 触发一次后多少秒内不再计数，避免连续重复报警。 |

**报警**

- 默认播放内置的双音警笛声，持续「报警时长」后自动停止；打开「一直响到手动停止」则持续到有人按下停止。
- 可以选择自己的 `.wav` 文件作为报警声；文件无法播放时自动改用内置警笛。
- 「试听报警声」用于确认音量——请在使用者的房间里实际试听，确认照护者能听到。

**外设（USB 继电器外接警报器）**

用一个 USB 继电器控制独立供电的声光警报器，让隔壁房间也能听到。

1. 适用 LCUS-1 型 USB 继电器（CH340 芯片，9600bps）。插上后如果电脑不识别，请安装 CH340 驱动。
2. 在「外设」页打开开关，选择继电器所在的串口（如 `COM3`；刚插上没看到就点「刷新」）。
3. 点「测试警报器」，继电器会吸合约 1 秒。
4. 报警时继电器吸合，停止报警（或报警时长到了）时断开。

> 继电器触点只是一个开关，用来接通警报器自己的电源（如 12V）。不要试图用 USB 直接给警报器供电。

**联动（Home Assistant / 米家）**

1. 在 Home Assistant 中新建一个由 Webhook 触发的自动化，得到形如
   `http://192.168.1.10:8123/api/webhook/blink_alarm` 的地址。
2. 在「联动」页打开开关，填入地址，请求方式选 `POST`。
3. 「附带内容」是随请求发送的 JSON，例如 `{"event": "blink_alarm"}`。软件会自动补充 `time` 和 `blinks`（测试时为 `test: true`）字段。
4. 点「发送测试」验证连通。

米家没有官方开放的 Webhook，可通过 Home Assistant 的米家集成中转，思路相同。

**高级**

镜像显示、是否显示眼睛轮廓、打开软件后自动开始监测、最短 / 最长闭眼时间（防抖参数，一般无需修改：闭眼太短或太长都不算一次眨眼），以及「重新校准」。
更换使用者、挪动了摄像头或光线明显变化后，建议重新校准一次。

### 常见问题

- **打不开摄像头**：换一个摄像头编号；关闭占用摄像头的其它软件（微信、钉钉、Zoom 等）；检查 Windows「隐私 → 摄像头」里是否允许桌面应用使用摄像头。
- **眨眼识别不到**：调高灵敏度；保证面部光线充足、避免强逆光和镜片反光；重新校准。
- **误触发频繁**：调低灵敏度，或增加眨眼次数、缩短时间窗口。
- **提示未检测到人脸**：让脸完整出现在画面中并尽量正对摄像头。人脸离开画面期间不会计数。
- **摄像头被拔掉**：软件会显示「正在重新连接」并自动重试，插回后继续监测。

## 三、工作原理

```
摄像头画面
   │  OpenCV 采集
   ▼
人脸检测（BlazeFace，仅在跟丢时运行）
   ▼
Face Mesh 478 点关键点（每帧运行；用上一帧的关键点跟踪下一帧的取样区域）
   ▼
左、右眼 EAR = (|p2-p6| + |p3-p5|) / (2·|p1-p4|)
   ▼
开合度 = EAR ÷ 睁眼基准（开始时校准约 2 秒，之后只在睁眼时缓慢自适应）
   ▼
每只眼睛一个状态机：开合度低于「闭眼阈值」→ 闭眼；回升到「睁眼阈值」→ 完成一次眨眼
（闭眼时长需在 最短~最长 之间；两只眼睛 250 毫秒内完成的算同一次）
   ▼
时间窗口内累计达到目标次数 → 报警（声音 + USB 继电器 + Webhook）→ 进入冷却
```

报警判定全部在后台检测线程完成，不受界面卡顿影响。

## 四、开发

需要 [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)。

```
dotnet test                              # 单元测试（算法 + 模型推理，可在任何系统上运行）
dotnet run --project src/BlinkAlarm.App  # 运行程序（Windows）
```

| 目录 | 内容 |
| --- | --- |
| `src/BlinkAlarm.Core` | 与界面无关的核心库：人脸关键点（`Vision/`）、眨眼判定与计数（`Blink/`）、Webhook 与警笛声（`Alarm/`）、设置（`Settings/`）、ONNX 模型（`Models/`） |
| `src/BlinkAlarm.App` | WPF 界面：`MainWindow.xaml`、主题样式（`Themes/`）、检测线程与声音（`Services/`）、视图模型（`ViewModels/`） |
| `tests/BlinkAlarm.Tests` | xUnit 测试 |
| `.github/workflows/build.yml` | 自动编译：测试 → 发布完整版和精简版 exe → 自检并截图 → 上传 |

发布后的 exe 支持 `BlinkAlarm.exe --self-test <输出文件夹>`：加载模型和原生库、把每个界面渲染一遍并保存截图，结果写入 `result.txt`。CI 用它确认打包出来的程序确实能启动。
